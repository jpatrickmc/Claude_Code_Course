# Site Contract: 3AM Datacenter — Static Landing Page

Derived from `PRD.md` and `contentmodel.md`. Governing constraint, applying to every section below: static HTML/CSS/JS only — no forms submitting to a backend, no authentication, no database, no build step. Every behaviour described here is achieved with CSS and vanilla JavaScript running entirely in the browser.

## 1. Page Structure

Visible sections, in page order:

1. **Header** — Identify the site with a single static mark, without introducing navigation the page doesn't need.
2. **Hero** — Establish the atmosphere and communicate the core proposition.
3. **Footer** — Close the page with attribution, without adding new claims or links.

Non-visible, precedes all rendered sections: **Site Meta** — satisfy the minimum requirements of a valid, sharable HTML document.

## 2. Content Inventory

**Site Meta**
- Page Title — string; ≤ 60 characters; required for any valid HTML document, independent of feature tier

**Header**
- Brand Mark — string; ≤ 20 characters; static text, monospace, no logo image or icon (Design Standard carries identity through type and color, not imagery)

**Hero**
- Headline — string; eight words maximum
- Subheadline — string; one sentence
- Primary CTA — label and section target; label ≤ 4 words, action-oriented; target must be an in-page anchor, `mailto:`, or external URL — never a form submission

**Footer**
- Brand / Copyright Line — string; ≤ 15 words; static text, year hard-coded at build time rather than generated by script

## 3. Behaviour Spec

**Navigation Behaviour**
- Single page, no routing and no secondary pages.
- The Brand Mark is static text, not a link — the Header has nothing to navigate to.
- The Primary CTA is the only navigation element on the page. Its target section isn't yet defined by the content model (only Header, Hero, and Footer exist) — this contract defaults the anchor to `#footer` as a placeholder until a real destination is set; treat that link as provisional, not final.

**Scroll Behaviour**
- Native browser scroll only — no scroll-jacking, no infinite scroll, no scroll-linked pinning.
- `scroll-behavior: smooth` on the anchor jump triggered by the Primary CTA.
- Smooth scroll is suppressed (jumps instantly) when `prefers-reduced-motion: reduce` is set.

**Hover States by Element Type**
- Primary CTA (button/link): background or text-color shift plus cursor:pointer on hover/focus; no layout shift; transition covers color/opacity only, not size or position.
- Brand Mark: none — static, non-interactive text.
- Copyright Line: none — static, non-interactive text.
- No other hoverable elements exist in the current content model.

**Mobile Layout Changes**
- Single breakpoint stack (e.g. ≤ 640px): Header, Hero, and Footer content shift from their desktop alignment to a centered, full-width single column.
- The Primary CTA becomes a full-width tap target on mobile rather than an inline-sized button, with a minimum 44px tap height.
- Typography scales down via fluid sizing (e.g. `clamp()`) rather than a hard breakpoint jump; vertical spacing between sections compresses proportionally.

**Transitions & Animations**
- Hero entrance: a single subdued fade/slide-in on page load (≤ 400ms, ease-out) — an enhancement, not a requirement, per PRD's Should-Have motion.
- `prefers-reduced-motion: reduce` disables the entrance transition and the smooth-scroll animation entirely; content and navigation remain fully functional either way.
- Primary CTA hover/focus transition: 150–200ms ease on color/opacity only.
- No ambient background motion, parallax, or decorative animation is included here — the PRD's Design Standard implies it, but no Must-Have content or behaviour in the current model calls for it. Add it as an explicit item if it's wanted at launch.

- Ambient/decorative motion referenced in the Design Standard has no corresponding behaviour spec here, matching the same gap already flagged in the content model.
